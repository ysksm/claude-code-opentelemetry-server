2. ダッシュボードの読み方

数値を読むときの注意

コストは概算

Claude Code がトークン数から計算した値で、請求額とは一致しない。サブスクリプションの席で使っている場合も、従量課金に換算した値が出る。

反映の遅れ

D′ は変換の間隔（既定 5 分）だけ遅れる。端末がオフラインの間の分は出ない。

案ごとの集計

  • B：外挿しない increase(…[…] anchored) で数える。メトリクスのコストとイベントの cost_usd の合計が一致することを実測で確認済み。推移は表示幅に応じた区間ごと。
  • D・D′：推移は 1 時間ごと。delta の値をそのまま合計する。

よく使う操作

  • 先月の利用者別コスト：期間「Previous month」→ パネルの ⋮ → Inspect → Data → Download CSV
  • 1 パネルを大きく：マウスを載せて v
  • SQL で分析（D・D′）：deploy/README.md の例

2. ダッシュボードの読み方

よく使う操作

やりたいこと操作
先月の利用者別コストを出す時間範囲で「Previous month」→「利用者別コスト」のパネルメニュー（⋮）→ Inspect → Data →「Download CSV」
特定のリポジトリだけ見る「リポジトリ別コスト」で確認。詳しくは Explore で vcs_repository_name（B）／ LogAttributes['vcs.repository.name']（D）で絞る

ダッシュボードはファイルから読み込んでいる（allowUiUpdates: false）。変えたいときは「Save as」で複製するか、deploy/<案>/grafana/dashboards/claude-code.json を 3 案そろえて変え、プルリクエストを出す。

3. 利用者の追加

オンボーディングは 4 ステップ

1

証明書を取り出す

内部 CA のときだけ。

docker compose cp \
 caddy:/data/caddy/pki/\
authorities/local/root.crt \
 ./caddy-root.crt
2

3 点を渡す

スクリプト、caddy-root.crt、URL とトークン。トークンはチャットに貼らず、パスワード管理ツールなどで。

3

利用者が実行

setup-client.sh を実行し、Claude Code を再起動してもらう。

4

届いたか確かめる

「利用者別コスト」にそのメールアドレスが出れば完了。出なければ利用者に --check。

組織で一括して配る

  • 端末ごとに sudo … --scope managed（利用者は外せない）
  • MDM なら --print の出力を managed-settings.json として配る

部署・チームで集計する

--attributes department=eng,team.id=platform。B では Prometheus のラベル（department・team.id・cost_center・enduser.id）、D・D′ では resource attributes に入る。

4. 閲覧アカウント

見る人には Viewer のアカウントを作る

作り方

  1. admin でログイン
  2. Administration → Users and access → Users → New user
  3. 名前・メール・ユーザー名・初期パスワードを入れる
  4. Organizations で役割を選ぶ

admin は管理専用にして、普段は使わない。

役割できること渡す相手
Viewerダッシュボードを見る、CSV を落とすチームリーダー、管理部門
Editorダッシュボードの複製・作成、Explore でクエリ分析する人
Adminユーザー管理、データソースの変更サーバーの運用者だけ
利用者別コストや Bash コマンドは個人の作業内容に関わる。誰に見せるかを先に決めてから、必要な人だけに作る。

5. 日々の運用

確認・トークンの入れ替え・バックアップ

届いているか

docker compose ps
docker compose logs \
  --since 10m collector

ダッシュボードの「イベント種別ごとの件数」が増えていれば、保存先まで届いている。

トークンの入れ替え

漏れたとき・退職者が出たとき。

  1. .env の OTEL_INGEST_TOKEN を新しい値に（openssl rand -hex 32）
  2. docker compose up -d collector
  3. 全員に setup-client.sh をもう一度実行してもらう

バックアップ

  • B：prometheus-data、loki-data
  • D：clickhouse-data
  • D′：data/（raw/ が原本）
  • 共通：grafana-data、caddy-data（CA の鍵。失うと証明書の配り直し）、.env

バージョンを上げるときは .env の *_VERSION を変えてプルリクエスト → docker compose pull && docker compose up -d。

5. 日々の運用

保持期間とディスク、バージョンの更新

案設定（.env）既定
BPROMETHEUS_RETENTION、LOKI_RETENTION400 日、90 日（2160h）
DCLICKHOUSE_TTL（テーブル作成時にだけ反映）2 年（17520h）
D′RAW_RETENTION_DAYS（JSONL の原本）、PARQUET_RETENTION_DAYS（0 = 消さない）400 日、消さない

変えたら docker compose up -d で反映。ディスクの使用量は docker system df -v（D′ は du -sh data/*）。

バージョンを上げる

  1. .env の *_VERSION を変えてプルリクエスト
  2. docker compose pull（D′ は docker compose build も）
  3. docker compose up -d
保持期間は組織の方針で決め、利用者にも知らせる（docs/overview.html に既定値を載せている）。

6. 困ったとき

症状から確かめること（利用者の端末）

症状確かめること
ある利用者のデータが出ない利用者に setup-client.sh --check。OK なら Claude Code を再起動したか（設定は起動時に読まれる）。リポジトリの .claude/settings.json に書いていないか（OTel の設定は無視される）
--check が 401トークンが違う。入れ替え前の古いトークンを使っていないか
--check が「証明書を検証できません」--ca-cert で caddy-root.crt を渡したか。Caddy のボリュームを作り直して CA が変わっていないか
--check は OK なのにデータが来ない--check は curl で確かめるので、Claude Code 側の証明書の読み込みまでは確かめていない。再起動したか確認し、だめなら NODE_EXTRA_CA_CERTS=~/.claude/otel/ca.crt をシェルの環境変数にも設定して試す
「サーバーに接続できません」端末から 443 番に届くか（VPN・ファイアウォール）。SITE_ADDRESS の名前を引けるか

6. 困ったとき

症状から確かめること（サーバーと画面）

症状確かめること
ブラウザで Grafana が証明書エラーcaddy-root.crt を OS の信頼ストアに入れる
全員分のデータが止まったdocker compose ps と docker compose logs collector。D は ClickHouse、B は Prometheus・Loki が動いているか。ディスクが一杯になっていないか
D′ で直近のデータだけ出ない変換の間隔（既定 5 分）を待つ。docker compose logs converter
「実行された Bash コマンド」が空利用者側で --tool-details（OTEL_LOG_TOOL_DETAILS=1）を付けていない。付けるかは組織の方針
リポジトリ別コストが空欄Git リポジトリの外で使っている、または OTEL_METRICS_INCLUDE_REPOSITORY が入っていない
コストが請求額と合わないダッシュボードの値は概算（「数値を読むときの注意」）

Summary

まとめと資料

押さえておくこと

  • ダッシュボードは 3 案とも同じ 12 パネル。期間は右上で選ぶ。
  • コストは概算。D′ は最大 5 分遅れる。
  • 利用者の追加は setup-client.sh と証明書・URL・トークンを渡すだけ。
  • 閲覧者は Viewer で、必要な人だけに。
  • caddy-data と .env もバックアップする。
