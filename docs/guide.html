Access

どこにアクセスするか：1 つのアドレスで全部そろう

<SITE_ADDRESS> はサーバーの .env に書いたホスト名（例 otel.example.internal）。分からなければ管理者に聞く。

開くものURLだれが
資料一覧（ここから始める）https://<SITE_ADDRESS>/docs/だれでも
管理画面（Grafana）https://<SITE_ADDRESS>/運用者・閲覧者（要アカウント）
端末の設定ファイル（スクリプト・証明書）https://<SITE_ADDRESS>/client/利用者
データの送り先https://<SITE_ADDRESS>/v1/…Claude Code（ブラウザでは開かない）
ブラウザが証明書を警告するときは、/client/caddy-root.crt を落として OS の信頼ストアに入れる（社内 CA のため）。
サーバー上で試すだけなら SITE_ADDRESS=localhost にして https://localhost/docs/。

1. 目的

何のために集めるのか

費用を把握する

誰が・どのリポジトリで・どのモデルにいくら使っているか（概算）を、請求を待たずに日単位で見る。

パネル：コスト、モデル別、利用者別、リポジトリ別

使い方を知って広げる

よく使われる Skill やツール、失敗の多い操作を見つけ、手順書や Skill の整備に生かす。

パネル：Skill の発動、ツール実行の結果

監査に備える 任意

組織で有効にした場合だけ、Claude Code が実行した Bash コマンドの記録を残す。

パネル：実行された Bash コマンド（D・D′）

個人の評価に使うことは目的にしていない。誰が見るか・何に使うかは導入する組織が決め、利用者に知らせる。

いつ送るか

使っている間、メトリクスは 1 分ごと、イベントは数秒ごとにまとめて送る。

どこへ送るか

社内の収集サーバーだけ。共通のトークンを持つ端末からしか受け付けない。

失敗したら

Claude Code はそのまま動く。届かなかった分のデータが欠けるだけ。

3. 送られるもの

数値と出来事は送る。中身（プロンプト・コード）は送らない

送られるもの

利用者メールアドレス、アカウント・組織 ID、セッション ID
環境バージョン、OS・端末の種類、Git リポジトリ名
メトリクスコスト（概算 USD）、トークン数、セッション数、変更行数、コミット・PR 数、操作時間
イベントAPI 呼び出し（モデル・トークン・コスト）、ツールの実行結果と許可・拒否、Skill の起動、エラー、プロンプトの長さ
任意department・team.id など（設定で付けた場合）

送られないもの（既定）

  • プロンプトの本文（何を頼んだか）
  • コード・ファイルの中身、Claude の応答の本文
  • Bash コマンドの全文などツールの詳細

組織が有効にした場合だけ

OTEL_LOG_TOOL_DETAILS=1（--tool-details）で、Bash コマンドの全文とツールの引数が送られる。

コマンドに含まれるパスワードやトークンも保存される。閲覧権限とバックアップ先が耐えられるかを先に決める。

4. 閲覧と保存

誰が見るのか、どのくらい残るのか

誰が見るのか

  • 管理画面（Grafana）は、管理者がアカウントを作った人だけが見られる。自分でアカウントは作れない。
  • 見えるのは、利用者別・リポジトリ別のコスト、ツール・Skill の利用回数など。
  • Viewer にも「実行された Bash コマンド」は見える。必要な人にだけアカウントを渡す。
  • 自分のデータを見たいときは管理者に頼む（アカウントか CSV）。

どのくらい残るのか（既定）

案保存先期間
BPrometheus ／ Loki数値 400 日 ／ イベント 90 日
DClickHouse2 年
D′JSONL ／ Parquet原本 400 日 ／ 削除しない

組織の方針に合わせて .env で変えられる。

5. 端末の設定

スクリプト 1 本で設定する（macOS / Linux）

用意するもの

  • https://<SITE_ADDRESS>/client/ から setup-client.sh と caddy-root.crt（社内 CA の証明書）を落とす
  • トークンは管理者から受け取る（Web には置いていない）

スクリプトがすること

  1. 接続・トークン・証明書を確かめる。だめなら何も書き換えずに止まる
  2. 証明書を ~/.claude/otel/ca.crt に置く
  3. ~/.claude/settings.json の env に書き足す（他の設定は変えない、バックアップを取る、権限 600）
# トークンは履歴に残らないよう環境変数で渡す（省くと入力を求められる）
$ OTEL_INGEST_TOKEN=<トークン> ./setup-client.sh \
    --endpoint https://otel.example.internal \
    --ca-cert  ./caddy-root.crt
==> 接続確認 OK（…/v1/metrics が 200 を返しました）
==> 証明書を配置: ~/.claude/otel/ca.crt
==> バックアップ: ~/.claude/settings.json.bak.20261012…
==> 書き込み: ~/.claude/settings.json
やりたいことオプション
内容を確かめる（書き換えない）--print
つながるか確かめる--check
送信を止める--uninstall
部署を付ける--attributes department=eng
Bash コマンドも送る（組織の方針で）--tool-details
組織で配る（root）--scope managed

設定のあとに起動した Claude Code から送信が始まる。Windows は settings.json を手で入れる。

7. ダッシュボードの読み方

数値を読むときの注意

コストは概算

Claude Code がトークン数から計算した値で、請求額とは一致しない。サブスクリプションの席で使っている場合も、従量課金に換算した値が出る。

反映の遅れ

D′ は変換の間隔（既定 5 分）だけ遅れる。端末がオフラインの間の分は出ない。

案ごとの集計

  • B：外挿しない increase(…[…] anchored) で数える。メトリクスのコストとイベントの cost_usd の合計が一致することを実測で確認済み。推移は表示幅に応じた区間ごと。
  • D・D′：推移は 1 時間ごと。delta の値をそのまま合計する。

よく使う操作

  • 先月の利用者別コスト：期間「Previous month」→ パネルの ⋮ → Inspect → Data → Download CSV
  • 1 パネルを大きく：マウスを載せて v
  • SQL で分析（D・D′）：deploy/README.md の例

8. 利用者の追加

オンボーディングは 4 ステップ

1

URL を知らせる

https://<SITE_ADDRESS>/docs/。手順・スクリプト・証明書はそこからたどれる。

2

トークンを渡す

トークンだけは Web に置いていない。チャットに貼らず、パスワード管理ツールなどで渡す。

3

利用者が実行

setup-client.sh を実行し、Claude Code を再起動してもらう。

4

届いたか確かめる

「利用者別コスト」にそのメールアドレスが出れば完了。出なければ利用者に --check。

組織で一括して配る

  • 端末ごとに sudo … --scope managed（利用者は外せない）
  • MDM なら --print の出力を managed-settings.json として配る

部署・チームで集計する

--attributes department=eng,team.id=platform。B では Prometheus のラベル（department・team.id・cost_center・enduser.id）、D・D′ では resource attributes に入る。

9. 閲覧アカウント

見る人には Viewer のアカウントを作る

作り方

  1. admin でログイン
  2. Administration → Users and access → Users → New user
  3. 名前・メール・ユーザー名・初期パスワードを入れる
  4. Organizations で役割を選ぶ

admin は管理専用にして、普段は使わない。

役割できること渡す相手
Viewerダッシュボードを見る、CSV を落とすチームリーダー、管理部門
Editorダッシュボードの複製・作成、Explore でクエリ分析する人
Adminユーザー管理、データソースの変更サーバーの運用者だけ
利用者別コストや Bash コマンドは個人の作業内容に関わる。誰に見せるかを先に決めてから、必要な人だけに作る。

10. 日々の運用

確認・トークンの入れ替え・バックアップ

届いているか

docker compose ps
docker compose logs \
  --since 10m collector

ダッシュボードの「イベント種別ごとの件数」が増えていれば、保存先まで届いている。

トークンの入れ替え

漏れたとき・退職者が出たとき。

  1. .env の OTEL_INGEST_TOKEN を新しい値に（openssl rand -hex 32）
  2. docker compose up -d collector
  3. 全員に setup-client.sh をもう一度実行してもらう

バックアップ

  • B：prometheus-data、loki-data
  • D：clickhouse-data
  • D′：data/（raw/ が原本）
  • 共通：grafana-data、caddy-data（CA の鍵。失うと証明書の配り直し）、.env

バージョンを上げるときは .env の *_VERSION を変えてプルリクエスト → docker compose pull && docker compose up -d。

10. 困ったとき

症状から確かめること

症状確かめること
ある利用者のデータが出ない利用者に setup-client.sh --check。OK なら Claude Code を再起動したか。リポジトリの .claude/settings.json に書いていないか（OTel の設定は無視される）
--check が 401トークンが違う。入れ替え前の古いトークンではないか
「証明書を検証できません」--ca-cert で caddy-root.crt を渡したか。Caddy のボリュームを作り直して CA が変わっていないか
--check は OK なのにデータが来ないClaude Code を再起動したか。だめなら NODE_EXTRA_CA_CERTS をシェルの環境変数にも設定
「サーバーに接続できません」端末から 443 番に届くか（VPN・ファイアウォール）。ホスト名を引けるか
全員分が止まったdocker compose ps と Collector のログ。保存先（Prometheus・Loki ／ ClickHouse）が動いているか。ディスクの空き
D′ で直近だけ出ない変換の間隔（既定 5 分）を待つ。docker compose logs converter
Bash コマンドが空利用者側で --tool-details を付けていない（付けるかは組織の方針）
リポジトリ別が空欄Git リポジトリの外で使っている

Summary

まとめと資料

資料はすべて https://<SITE_ADDRESS>/docs/ から開ける。

押さえておくこと

  • 送るのは数値と出来事。プロンプトやコードの中身は送らない。
  • Bash コマンドの記録は組織が有効にしたときだけ。
  • 端末の設定は setup-client.sh 1 本。既存の設定は壊さず、--uninstall で戻せる。
  • コストは概算。請求額とは一致しない。
  • 閲覧者は必要な人だけ。Viewer で渡す。
